## 要求2：实现基本循环

### 2.1 主循环四步

题目要求 Loop：接收输入 → 判断直接回复还是调工具 → 调工具 → 根据结果继续 loop 或返回。

- **实现**：`agent/runtime.py` 的 `AgentRuntime.run()`，`max_turns` 控制循环上限。
- **验证**：
  - `test_runtime.py::test_direct_answer` —— 直接回复分支；
  - `test_runtime.py::test_tool_loop_converges` —— 工具调用后继续 loop 直至返回；
  - **真实 API 冒烟**：算数用例可见完整 trace（`LLM 决策 → tool_call calculator → 结果 640 → answer`）。

### 2.2 工具：至少 3 个 + 注册机制 + 输出解析

- **3 个工具**：`calculator`（ast 白名单安全计算）、`search`（mock 检索）、`todo`（会话级待办）。
- **注册机制**：每个工具含 `name` + `description` + `parameters`（JSON Schema），`ToolRegistry.to_openai_schema()` 转成 OpenAI `tools` 参数，LLM 据此自主决策。
- **输出解析**：`parser.py` 提取思考过程（`reasoning_content`）、工具调用（原生 `tool_calls` + JSON 兜底）、最终答案。
- **验证**：
  - `test_tool_registry.py` 全部 7 例（注册/Schema/重复注册/未知工具/异常兜底/隐藏参数注入）；
  - `test_parser.py` 全部 6 例（原生 tool_calls、最终答案、JSON 兜底、非法输入）；
  - 冒烟测试确认 LLM 真实自主决策调用 `calculator`、`todo`。

### 2.3 Session 管理（多窗口隔离）

- **实现**：`session.py` 的 `SessionManager` 以 `session_id` 隔离；`todo` 工具通过 `context` 注入隐藏参数 `session_id` 实现会话级数据隔离。
- **验证**：
  - `test_session.py` 全部 3 例；
  - `test_runtime.py::test_multi_session_runs_independently`；
  - **真实 API 冒烟**：窗口1 记「查天气」、窗口2 记「写周报」，切回窗口1 只能看到「查天气」，隔离成立。

### 2.4 Context 有效管理

- **最大轮次限制**：`max_turns`，超限返回兜底 —— `test_max_turns_fallback` ✅
- **记住之前状态 / 追问**：历史消息完整保留；带工具追问 —— `test_followup_with_tool` ✅（"再乘以 2" 基于上一轮结果继续调工具）
- **基础压缩**：超 `max_history_messages` 用 LLM 摘要最老消息 —— `test_compress_history_triggers_summary`、`test_no_compress_when_under_limit` ✅
- **memory 召回时机与放置方式**：详见 `README.md`「Memory 设计」一节。

### 2.5 额外要求：异常处理 + trace 日志

- **异常处理**：LLM 异常兜底 —— `test_llm_error_is_handled` ✅；工具内部异常兜底 —— `test_call_tool_exception_is_caught` ✅
- **trace 日志**：`_log_trace()` 输出 `[trace_id][event]` 结构化日志（input / llm / tool_call / answer），冒烟测试输出中可完整看到。
